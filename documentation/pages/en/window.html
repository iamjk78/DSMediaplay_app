Account, login and password

  • Customer Account and Login: select the account and the login. The + and − buttons next to them add or remove an account or a login (with the stored passwords). The address of an account must start with https://.
  • Password and “Save Login Details”: the application logs in to the server with the details; when that works, it stores the password in the password store (the macOS Keychain, the Windows Credential Manager). The password is never written to the configuration file.
  • A user of a customer account (a collaborator) has an address ending in _xxxx (four letters after the last underscore). The application uses the address of the main account, where the players are, and says so in the log.
  • The buttons Start, DEPLOY ALL, Live-view and Outages are grey until an account, a login and a password are given. Start also needs a selected action.

Category and action

In “Select Category” select a category (Playlists, Groups, Players, Locations, Assets, Deploy), in “Select Action” an action. The actions that start with “CSV” download a file, the others change data on the server. All the actions are described on the pages of the categories.

The entries of the list of actions are coloured by what they do: green for downloading a CSV file, blue for setting, adding, renaming and creating, red for removing and deleting. Each colour is a block of its own, and the actions in it are in alphabetical order. When the pointer rests on an action in the list, a description of it appears next to it.

The application remembers the last used account, login, category and action and selects them again the next time it starts. An action that removes or deletes is not restored, only its category.

Input

The “Input Prompt” button is shown only for actions that take input. The window holds a template: the grey lines starting with # describe the columns, the last line is an example. You can delete the template or leave it, the lines of it that were not changed are skipped. The columns are separated by tabs (pasting from a spreadsheet does it), one record is one line. The lines are processed in the order they are written, and errors give the number of the line as you see it.

The input is checked as a whole before anything is changed: when something in it is wrong (an unknown name, a wrong date or time), nothing is done and the log lists all the errors.

The log first says how many lines it read and how many empty lines between them it skips. A line that is in the input more than once is processed only once; the log says how many repeated lines it skipped. At the end of the log all the errors are listed once more in red under the heading “Errors found:”. A click on an underlined line of such an error opens the input with the text of the last run and the cursor on the line with the error.

Running and the log window

“Start” opens the log window. It shows the progress and the state (Working, Done, Error, Cancelled, Stopped). The buttons:

  • STOP: stops the operation when the batch being processed is finished. What has been done is not undone. After a stop the log says after how many steps the operation ended.
  • Close: closes the window; when the operation is still running, it asks first and stops it.
  • Save: saves the log to a text file.

Before something that cannot be undone (deleting, deploy) the log window shows what is going to happen (the list, the number of players) and asks; the default answer is “No”.

Before an action that overwrites or deletes data (for example setting the playlists of groups, removing playlists, deleting unused items) the application saves the state before the change to the Downloads folder as CSV files named account-backup-data-time.csv. The log says where they were saved. When the backup cannot be saved, the action does not start. Creating, adding and renaming are not backed up, the log shows the old and the new value.

CSV files

The “CSV - …” actions save a file to the Downloads folder as account-action-date.csv and say the path when done. The file is separated by semicolons, in UTF-8 with the mark spreadsheet applications need, so the accents open correctly. A text in the file that starts with = or @, or is a word with a sign, gets an apostrophe in front so a spreadsheet does not run it as a formula.

The quick buttons

  • Outages: the table of the players prefiltered to the active players that are offline, with the newest report at the top.
  • Live-view: the table of all the players with screenshots. See The table of players.
  • DEPLOY ALL: a deploy to all the online players of the account. Their number is shown and confirmed first.

Settings and help

The “Settings” button: language, font, font size and Deploy (the size of a batch and the interval between batches in seconds). A new language or font applies to the whole window after saving; changing the batch closes nothing. “Restore defaults” returns the defaults. The title of the window shows the version of the application. The “Help” button opens this guide.

If something does not work

  • The login could not be verified: check the password and the internet connection. A server error (code 5xx) is reported separately, it is not a wrong password.
  • An error in the input: the log gives the number of the line and the reason; save the input again after the correction.
  • A damaged accounts file: at the start the application asks whether to keep it next to itself under another name and begin with an empty list. The passwords stay in the password store.
  • The help does not open: the application uses a free port when 8080 is taken by another application.
